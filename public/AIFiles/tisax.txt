TISAX Program Configuration
Version: 6.0.3

1. Locations
   └── Headquarters
       ├── Sublocation 1
       └── Sublocation 2
   (Each sublocation inherits settings from Headquarters unless overridden.)

2. Assessment Levels
   AL2
     • Modules:
       – Information Security
         · Controls: (to be populated from ISA catalogue)
       – Prototype Protection
         · Controls: (to be populated from Prototype Protection catalogue)

   AL3
     • Modules:
       – Information Security
         · Controls: (same as AL2)
       – Prototype Protection
         · Controls: (same as AL2)
       – Additional Data Protection
         · Controls: (to be populated from Data Protection catalogue)

3. Controls
   For each module, each control entry includes:
     • Control ID (e.g. “1.1.1”)
     • Control question
     • Objective
     • Requirements:
         – Must-requirements (list of questions)
         – Should-requirements (list of questions)
         – Additional requirements (by protection need)
     • Reference documentation links (URL or document ID)
     • Uploaded evidence files (list of file references)
     • Findings, comments, deviation flags

4. Assignment Workflow
   • Roles:
     – Assigner (one per location)
     – Employee (multiple per location)
     – Reviewer (multiple per location)
   • At each location:
     – The Assigner assigns specific controls to Employees.
     – The Assigner also designates a Reviewer for each assigned control.
     – Employees complete their assigned controls (answer requirements, upload evidence).
     – Reviewers review and mark controls as ready or flag deviations.

5. Task Management (per Control)
   • For any control, users may:
     – Create one or more granular tasks (e.g. “Collect policy document”, “Schedule risk assessment”).
     – Attach/upload files or evidence to each task.
     – Track task status (Open / In-Progress / Done).
     – Set due dates and reminders.
     – Link tasks back to their parent control.

6. Reference Documentation
   • Global library of documents (policies, templates, guidelines).
   • Each control may reference one or more library items or external URLs.
   • Versioning and review date for each referenced document.
